## Regla central

No asumir cumplimiento porque exista una pantalla, formulario, dashboard o CRUD. Verificar funcionamiento real en frontend, backend, persistencia, base de datos, APIs, roles, reglas de negocio, flujos, integraciones, reportes, georreferenciación, evidencia y componentes analíticos/IA cuando corresponda.

La documentación distingue requisitos confirmados, flujo institucional, inferencias técnicas y decisiones pendientes. No convertir una inferencia en obligación contractual.

Antes de modificar cualquier software, producir primero un diagnóstico documental y técnico.
